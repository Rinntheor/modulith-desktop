# 宿主接口参考 —— 参考插件

**这个插件不提供任何功能。** 它把不需要危险权限的核心宿主接口逐个调一遍，并把「刚才调用的
是哪个接口、它需要哪项权限」直接显示在界面上 —— 于是一份示例既是代码，也是它自己的说明书。

它的用途是**给写插件的人读**：想照着写一个插件，从这里开始。

## 功能

| 功能 | 怎么用 |
| --- | --- |
| 记一次 | 「记一次」按钮，数字加一并写进插件的私有存储；重启应用后仍在 |
| 清空存储 | 「清空存储」调用存储的删除接口 |
| 四种通知 | 四个按钮分别发 info / success / warn / error 四级的应用内通知 |
| 发布事件 | 向事件总线发一条消息（本插件收不到自己的消息，原因见下） |
| 窗口级快捷键 | 本模块可见时按 `Ctrl+Shift+E` 会记一条；切到别的模块就不响应了 |
| 调用记录 | 每次操作都会在页面底部留下一行「调用了什么、需要什么权限」 |
| 全局搜索命令 | 在标题栏搜索框里搜「参考插件」，会看到它注册的命令 |

## 它示范了什么

| 约定 | 接口 | 需要哪项权限 |
| --- | --- | --- |
| 加载期取上下文 | `createContext()` | 无 |
| 注册一个模块（必须同步调用） | `registerModule()` | 无 |
| 注册一条全局搜索命令 | `registerCommand()` | 无 |
| 私有持久化存储 | `storage` | `storage` |
| 应用内通知 | `notifications` | `notification` |
| 插件之间通信 | `events` | `plugin-communicate` |
| 日志（输出到控制台） | `logger` | 无 |
| 判断模块是否可见 | `useModuleActive()` | 无 |
| 插件自己的样式与深色模式 | `index.css`（`rf-` 前缀） | 无 |
| SVG 图标 | `icon.svg` | 无 |

**需要原生能力的接口刻意不在这里**：启动本机程序、提取文件图标、在文件管理器中定位、接收
拖入的文件、导入音频。装一个「示例插件」却要同意 `process-spawn` 或读文件，本身就是对
「权限列表是给用户看风险用的」这条原则的反面示范。想看那几项怎么写，读插件仓库里的
`quick-launch`（原生能力）与 `pomodoro`（后台计时 + 通知 + 自定义提示音）。

## 四处值得注意的写法

### 注册必须在加载期同步完成

```js
Modulith.registerModule({ id: 'reference', name: '…', component: Reference });
```

放在 IIFE 顶层，不能包进 Promise、`setTimeout` 或任何回调。宿主在一次加载结束后**立即**
检查注册结果，晚一步就会被判定为「没有注册任何模块」，插件被标记为异常。

### 窗口级监听必须判断模块是否可见

标签页保活意味着模块被切走后**不会卸载**。`keydown`、拖放这类窗口级监听如果不判断可见性，
就会在别的模块里也生效 —— 与其它插件抢快捷键、抢拖入的文件：

```js
var active = Modulith.useModuleActive();
React.useEffect(function () {
  if (!active) return;              // 少了这一行，别的模块里按同一个组合键也会触发本插件
  window.addEventListener('keydown', onKeyDown);
  return function () { window.removeEventListener('keydown', onKeyDown); };
}, [active]);
```

这是插件最容易犯、又最难自查的错误：开发时你总停在这个模块里测试。

### 插件收不到自己发布的事件

只装这一个插件时，「已收到事件」永远是 0。**这不是坏了。** 宿主默认不让插件收到自己发布
的事件（`receiveOwn` 默认 false），理由是「发布之后由自己订阅来更新界面」这种写法会绕一圈
回到自己，而处理函数里再发布同一主题就成了死循环。

需要自己处理自己时应当直接改状态，而不是绕经事件总线。要看到事件真的到达，需要第二个插件
向同一主题发布。

### 存储与 localStorage 不是一回事

| | 插件存储 | `localStorage` |
| --- | --- | --- |
| 隔离 | 按插件 ID 隔离 | 全应用共用一份命名空间 |
| 清理 | 卸载插件时一并删除 | 永久残留 |
| 值类型 | JSON 序列化，可存对象 | 只能存字符串 |
| 权限 | 需声明 `storage` | 无需声明 |

存储键只允许字母数字与 `.` `_` `-`（最长 128 字符）；事件主题名只允许小写字母、数字与
`.` `_` `-`（最长 64 字符）。写错不会报错，而是被后端静默拒绝。

## 这个文件里的一条规矩

本仓库的 `pnpm check:samples` 会按**文本**扫描 `index.js` 里所有形如 `ctx.` 加服务名的片段
—— **包括注释** —— 再与清单的 `permissions` 比对。两种不一致都算失败：

- 代码用了某能力、清单没声明 → 运行时会被拒绝，而且是用户点到那一步才发现；
- 清单声明了、代码里没用到 → 用户在安装确认页会看到一条并不存在的能力。

因此 `index.js` 的开头提到那几项原生能力时只写了接口名，没有加 `ctx.` 前缀。

## 用到的权限

只声明三项：`storage`、`notification`、`plugin-communicate`，全部与「读本机文件」「执行本机
程序」「联网」无关。

**权限列表是给用户看风险用的，多写一项就多一分误导。** 应用会把每项权限换算成风险等级
展示给用户，而换算规则由宿主统一推导 —— 插件无法自己声明「我很安全」。

## 目录结构

```
reference/
├── manifest.json      清单（storage / notification / plugin-communicate）
├── index.js           手写 IIFE，无构建步骤
├── index.css          插件自带样式，含深色模式
├── icon.svg           图标（SVG 文本会被直接内联渲染）
├── README.md          会显示在插件详情抽屉里
└── LICENSE            MIT
```

打成 `.lcp` 就是把该目录压缩后改扩展名：

```powershell
Compress-Archive -Path .\samples\reference\* -DestinationPath .\samples\reference.lcp -Force
```

> 改完源码**必须重新打包**，否则从包安装到的还是旧代码。`cargo test` 里有一条检查会解压
> 这个包、逐字节比对源码目录与包内文件，忘记打包会直接失败。
