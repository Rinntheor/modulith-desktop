# 环境搭建

本文说明开发 Modulith 所需的工具链、安装步骤与验证方法。

## 1. 工具链要求

| 工具 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | 22 或更高 | `chalk@6` 声明 `engines.node >= 22`，脚本依赖 Node 原生 TypeScript 类型擦除 |
| pnpm | 9 或更高 | 项目使用 pnpm 工作区 |
| Rust | 稳定版工具链 | crate 使用 edition 2021 |
| Tauri CLI | 2.x | 由 `@tauri-apps/cli` 以开发依赖形式提供，无需全局安装 |

Node 版本尤为重要：`scripts/` 下的脚本以 `node scripts/xxx.ts` 直接运行，依赖 Node 对 TypeScript 的类型擦除能力，因此不需要 `tsx` 或 `ts-node`。这也意味着脚本内部的相对导入必须带 `.ts` 扩展名。

## 2. 平台依赖

Tauri 需要系统提供 WebView 与原生编译工具链。

**Windows**

- Microsoft C++ Build Tools，需包含「使用 C++ 的桌面开发」工作负载
- WebView2 Runtime（Windows 11 已内置；Windows 10 通常也已随 Edge 安装）

**macOS**

- Xcode Command Line Tools：`xcode-select --install`

**Linux**

- 需要 WebKitGTK 与相关开发包，具体包名依发行版而定。以 Debian 系为例，通常需要 `libwebkit2gtk-4.1-dev`、`libssl-dev`、`libayatana-appindicator3-dev`、`librsvg2-dev`、`build-essential`。

## 3. 获取代码与安装依赖

```bash
git clone <仓库地址>
cd modulith-desktop
pnpm install
```

首次安装会拉取前端依赖与 Rust crate，Rust 侧编译耗时较长。

## 4. 运行

```bash
pnpm dev          # 仅启动前端开发服务器（Vite，端口 1420）
pnpm tauri dev    # 启动完整桌面应用（推荐）
```

`pnpm dev` 只运行前端，窗口与后端命令不可用，适合调整纯界面部分。完整开发应使用 `pnpm tauri dev`。

两个命令都会先执行版本一致性校验与后端代码生成，因此首次运行会自动产出所需文件。

## 5. 构建

```bash
pnpm build        # 前端类型检查 + 生产构建
pnpm tauri build  # 完整应用打包
```

`pnpm tauri build` 会通过 `tauri.conf.json` 中的 `beforeBuildCommand` 自动调用 `pnpm build`，无需手动执行两次。

## 6. 常用命令

| 命令 | 用途 |
| --- | --- |
| `pnpm tauri dev` | 启动开发环境 |
| `pnpm tauri build` | 打包发布版本 |
| `pnpm gen:modules` | 重新生成前端模块注册表 |
| `pnpm gen:backend update` | 重新生成后端模块声明与命令注册 |
| `pnpm gen:backend list` | 查看后端模块与命令 |
| `pnpm ver show` | 查看当前版本 |
| `pnpm ver check` | 校验版本一致性 |
| `pnpm ver:fix` | 同步版本号到各配置文件 |
| `pnpm release` | 发布准备：预检 → 签名构建 → 生成更新清单（见[版本管理](版本管理.md) 第 7 节） |

各命令的细节见[构建与代码生成](构建与代码生成.md)与[版本管理](版本管理.md)。

## 7. 验证安装

依次执行以下命令，全部通过表示环境可用：

```bash
# 1. 版本文件一致
pnpm ver check

# 2. 类型检查通过
npx tsc -p tsconfig.json --noEmit

# 3. 后端可编译且测试通过
cd src-tauri && cargo test --offline --lib
```

后端测试覆盖认证加密、插件包解压安全、设置校验与应用信息等模块，全部通过说明 Rust 侧环境正常。

## 8. 常见问题

**Node 版本过低导致脚本报错**

表现为脚本启动即失败，提示语法或模块解析错误。请升级到 Node 22 或更高。

**`cargo` 编译失败并提示找不到链接器**

Windows 上通常是缺少 C++ Build Tools。安装时请确认勾选桌面开发工作负载。

**首次运行白屏**

按 F12 打开开发者工具查看控制台。启动流程会把失败步骤与原因显示在启动界面，通常可直接看出问题。若启动界面本身未出现，多为前端资源未正确构建。

**修改模块后界面没有变化**

Vite 插件会监听 `src/modules` 并按文件指纹判断是否需要重新生成。若确认已修改但未生效，可手动执行 `pnpm gen:modules`，并检查 `src/generated/generation.log.json` 中的诊断信息。

**构建提示版本不一致**

说明配置文件与 `version.toml` 不一致。执行 `pnpm ver:fix` 同步后重试。构建刻意不自动改写文件，以避免构建过程产生意外的工作区变更，详见[版本管理](版本管理.md)。
