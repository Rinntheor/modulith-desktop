# 快速开始

本文从零构建一个可安装的插件，包含清单、代码、打包与安装的完整过程。完成后你会在侧边栏看到自己的模块。

> **你写的插件归你所有，授权方式也由你决定。** 框架本身是 GPL-3.0，但依据 GPL-3.0 第 7 条附加的**插件例外**，只调用公开插件接口的插件不被视为框架的衍生作品 —— 你可以用 MIT、Apache-2.0，也可以闭源。前提是不要复制框架的实现代码。详见[版权与授权](../../07-法务/版权与授权.md)。

## 1. 插件的最小构成

一个可用的插件需要三样东西：

1. 一份 `manifest.json`，声明身份与入口。
2. 一个代码包，它是一个自执行脚本，运行时调用 `Modulith.registerModule()` 注册界面。
3. 可选资源：样式表、图标、说明文档。

代码包必须是自执行脚本而非 ES 模块，因为宿主通过注入 `<script>` 元素的方式执行它。

## 2. 创建目录

```
my-plugin/
  manifest.json
  dist/
    index.js
```

`dist/` 是约定的输出目录，清单中的路径都是相对插件根目录。

## 3. 编写清单

`my-plugin/manifest.json`：

```json
{
  "name": "com.example.hello",
  "displayName": "问候",
  "version": "1.0.0",
  "description": "一个最小可用的示例插件",
  "author": {
    "name": "你的名字"
  },
  "license": "MIT",
  "engines": {
    "loopcore": ">=1.0.0"
  },
  "main": "dist/index.js"
}
```

关于 `engines.loopcore`：使用 `>=1.0.0` 而不是 `^1.0.0`。两者都能匹配 1.x，但只带下界的写法在宿主升到下个大版本时也不会产生提示。详细规则见[清单文件参考](清单文件参考.md)。

## 4. 编写代码包

`my-plugin/dist/index.js`：

```js
(function () {
  'use strict';

  var Modulith = window.Modulith;
  if (!Modulith) {
    console.error('[hello] 宿主尚未就绪');
    return;
  }

  // 使用宿主提供的 React，不要自行导入
  var React = Modulith.React;
  var h = React.createElement;

  // 在加载期取得绑定到本插件的服务
  var ctx = Modulith.createContext();

  function Hello() {
    var state = React.useState(0);
    var count = state[0];
    var setCount = state[1];

    return h(
      'div',
      { style: { padding: '24px' } },
      h('h1', { style: { fontSize: '20px', fontWeight: 600 } }, '问候'),
      h('p', { style: { marginTop: '8px', color: '#6b7280' } }, '你点击了 ' + count + ' 次'),
      h(
        'button',
        {
          onClick: function () {
            setCount(count + 1);
            ctx.logger.info('计数变为', count + 1);
          },
          style: {
            marginTop: '16px',
            padding: '8px 16px',
            background: '#6366f1',
            color: '#fff',
            border: 'none',
            borderRadius: '8px',
            cursor: 'pointer',
          },
        },
        '点我'
      )
    );
  }

  Modulith.registerModule({
    id: 'helloView',
    name: '问候',
    displayName: '问候',
    description: '一个最小可用的示例插件',
    priority: 50,
    component: Hello,
  });

  ctx.logger.info('插件加载完成');
})();
```

这段代码体现了四条关键约定：

| 约定 | 原因 |
| --- | --- |
| 使用 `Modulith.React` | 插件与宿主必须共用同一份 React 实例，否则 Hooks 失效 |
| 在 IIFE 顶层调用 `createContext()` | 服务需要绑定正在加载的插件，之后调用会抛错 |
| 在顶层调用 `registerModule()` | 宿主在一次加载结束后立即检查注册结果 |
| 模块 `id` 不使用内建模块名 | 冲突会被拒绝并输出错误 |

## 5. 安装并验证

开发阶段推荐直接从目录安装，避免每次修改都重新打包。在应用的「设置」中打开「插件」分页，选择从本地目录安装，指向 `my-plugin` 目录。

安装后侧边栏应出现「问候」。点击应能正常计数。

如果未出现，按顺序检查：

1. 插件管理界面中该插件的状态。加载失败会显示具体原因。
2. 开发者工具的控制台，筛选 `[plugin:` 前缀。
3. 确认代码包确实调用了 `registerModule`，且模块 `id` 未与其他模块冲突。

## 6. 打包为 .lcp

`.lcp` 就是一个 zip 容器，扩展名用于标识与文件选择过滤。

```powershell
# Windows
Compress-Archive -Path .\my-plugin\* -DestinationPath .\my-plugin.lcp
```

```bash
# macOS 与 Linux
cd my-plugin && zip -r ../my-plugin.lcp . && cd ..
```

注意压缩的是目录**内容**而不是目录本身，因此 `manifest.json` 位于压缩包根部。如果压缩后多了一层目录，安装时会找不到清单。

打包后可通过从插件包安装来验证：

```
设置 > 插件 > 安装插件 > 从插件包安装
```

## 7. 添加样式

在插件中写内联样式会让代码冗长。更好的做法是提供独立样式表。

在清单中声明：

```json
{
  "main": "dist/index.js",
  "style": "dist/index.css"
}
```

`my-plugin/dist/index.css`：

```css
.hello-view {
  padding: 24px;
}

.hello-view__title {
  font-size: 20px;
  font-weight: 600;
}

.hello-view__button {
  margin-top: 16px;
  padding: 8px 16px;
  background: #6366f1;
  color: #fff;
  border: none;
  border-radius: 8px;
  cursor: pointer;
}
```

样式会在插件加载时注入页面，卸载时移除。因此建议为类名加上插件专属前缀，避免与宿主样式或其他插件冲突。

然后代码中改用类名：

```js
h('div', { className: 'hello-view' },
  h('h1', { className: 'hello-view__title' }, '问候'),
  h('button', { className: 'hello-view__button', onClick: handleClick }, '点我')
);
```

## 8. 添加自定义图标

放置 `my-plugin/icon.svg`，并在清单中声明：

```json
{ "icon": "icon.svg" }
```

图标必须是 SVG。以 `.svg` 结尾的路径会被当作文件读取，其他值会被当作 lucide-react 图标名处理。因此 `.png` 不受支持。

也可以直接内联 SVG 源码：

```json
{ "iconSvg": "<svg viewBox=\"0 0 24 24\"><circle cx=\"12\" cy=\"12\" r=\"8\"/></svg>" }
```

`iconSvg` 的优先级高于 `icon`。

## 9. 使用构建工具

手写 IIFE 适合小插件。功能复杂时应当引入打包器，把 TypeScript 与 JSX 编译为 IIFE。

关键是把 React 相关模块设为外部依赖，并映射到宿主提供的实例。以 Vite 为例：

```js
// vite.config.js
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  build: {
    lib: {
      entry: 'src/index.tsx',
      formats: ['iife'],
      name: 'MyPlugin',
      fileName: () => 'index.js',
    },
    rollupOptions: {
      // 不打包 React，改用宿主实例
      external: ['react', 'react/jsx-runtime'],
      output: {
        globals: {
          // import React from 'react' 与 import { useState } from 'react'
          // 都会落到 Modulith.React 上
          react: 'Modulith.React',
          // jsx / jsxs / Fragment 直接挂在 Modulith 上，
          // 因此这里映射到 Modulith 本身而不是某个子成员
          'react/jsx-runtime': 'Modulith',
        },
      },
    },
  },
});
```

对应的源码可以直接使用 JSX：

```tsx
// src/index.tsx
const Modulith = (window as any).Modulith;
const ctx = Modulith.createContext();

function Hello() {
  const [count, setCount] = React.useState(0);
  return <button onClick={() => setCount(count + 1)}>点击 {count}</button>;
}

Modulith.registerModule({ id: 'helloView', name: '问候', component: Hello });
```

两点说明：

- 映射 `react/jsx-runtime` 到 `Modulith` 而非 `Modulith.jsx` 是必要的。自动运行时会产生 `jsx`、`jsxs`、`Fragment` 三个命名导入，映射到父对象后，打包器会生成 `Modulith.jsx`、`Modulith.jsxs`、`Modulith.Fragment` 三种访问，与宿主实际提供的成员一致。
- 不要引入 `react-dom`。宿主负责挂载，插件只需交出组件。注意**宿主也不提供 `ReactDOM`**，因此「把 react-dom 外部化」并不能解决问题 —— 外部化之后它会被映射到一个不存在的全局成员，只是恰好因为没有被实际调用而不报错。正确做法是让依赖链不要带入它（多数 UI 库把它作为 peer 依赖，不会打进来）；真的带进来了，要先确认产物里没有对它的调用。

不同打包器的配置方式不同，但原理一致：React 系列全部外部化，映射到 `Modulith` 的对应成员。打包后建议按第 6 节的方式安装验证，确认没有出现「Invalid hook call」或「React is not defined」错误。

## 10. 调试建议

| 手段 | 用途 |
| --- | --- |
| 开发者工具控制台 | 筛选 `[plugin:` 前缀查看插件日志 |
| 插件管理界面 | 查看加载状态与失败原因 |
| 从目录安装 | 修改代码后重新加载即可生效，无需打包 |
| 标题栏刷新按钮 | 重新加载全部插件与模块 |

从目录安装时，修改插件代码后需要在插件管理界面重新触发加载（切换启用状态或使用标题栏刷新），因为已注入的脚本不会被自动替换。
