# 示例插件解析

仓库里保留**一个**参考插件：`samples/reference`。它不提供任何功能，只把不需要危险权限的
核心宿主接口逐个示范一遍，并把「刚才调的是哪个接口、它需要哪项权限」直接显示在界面上 ——
于是一份示例既是代码，也是它自己的说明书。本文逐节解析它。

三个**完整示例**（可用的插件，也是可以照着读的源码）在插件仓库
[`modulith-plugins`](https://github.com/Rinntheor/modulith-plugins)：

| 插件 | 侧重 | 参与的宿主能力 |
| --- | --- | --- |
| [`plugins/notes`](https://github.com/Rinntheor/modulith-plugins/tree/main/plugins/notes) | 一个完整插件的基本形态，只用一项权限 | `ctx.storage` |
| [`plugins/pomodoro`](https://github.com/Rinntheor/modulith-plugins/tree/main/plugins/pomodoro) | 后台计时、应用内通知、自定义提示音 | `ctx.storage`、`ctx.notifications`、`ctx.audio` |
| [`plugins/quick-launch`](https://github.com/Rinntheor/modulith-plugins/tree/main/plugins/quick-launch) | 需要宿主原生能力的插件怎么写 | `ctx.storage`、`ctx.launcher`、`ctx.icons`、`ctx.shell`、`ctx.fileDrop` |

它们可以从应用的插件市场直接安装，各自的 `README.md` 里有功能、权限与实现取舍；本文第 6 节
只留它们最关键的那几处设计。

## 1. 为什么还留一个「不提供功能」的示例

**因为示例的首要用途是被复制，而不是被使用。**

一旦示例开始提供功能，它就会长出设置项、边界处理与历史包袱 —— 那些东西是它作为「一个软件」
的价值，却是它作为「一份说明书」的负担。参考插件刻意只做一件事：把每个接口调一遍。

还有一个更实际的原因：**需要原生能力的接口不能塞进这个示例**。装一个「示例插件」却要同意
`process-spawn`（执行本机程序）或 `filesystem-read`（读本机文件），本身就是对「权限列表是给
用户看风险用的」这条原则的反面示范。所以这个示例只碰不需要危险权限的那部分，原生能力的
写法交给插件仓库里那两个真正需要它们的插件。

## 2. 目录结构与装包

```
reference/
├── manifest.json      清单（storage / notification / plugin-communicate）
├── index.js           手写 IIFE，无构建步骤
├── index.css          插件自带样式，含深色模式
├── icon.svg           图标（SVG 文本会被直接内联渲染）
├── README.md          会显示在插件详情抽屉里
└── LICENSE            MIT
```

**`main` 指向根目录的 `index.js` 而不是默认的 `dist/index.js`。** 默认值只是约定，不是要求；
示例刻意绕开 `dist/`，一是因为仓库的 `.gitignore` 排除了所有 `dist` 目录，二是因为「源码就在
你眼前」比「源码在构建产物背后」更适合当范例。

打成 `.lcp` 就是把该目录压缩后改扩展名：

```powershell
Compress-Archive -Path .\samples\reference\* -DestinationPath .\samples\reference.lcp -Force
```

> **`.lcp` 必须与源码目录逐字节一致。** 改完插件忘记重新打包，用户装到的就还是旧代码。
> 这条由 `extracts_and_validates_real_sample_lcps` 测试守着 —— 它解压这个 `.lcp`，逐个文件
> 与源码目录比对，同时校验清单。**这个错误我犯过两次，所以现在有测试兜着。**

## 3. 清单

```json
{
  "name": "com.modulith.sample.reference",
  "displayName": "宿主接口参考",
  "version": "1.0.0",
  "engines": { "loopcore": ">=1.0.0" },
  "main": "index.js",
  "style": "index.css",
  "icon": "icon.svg",
  "permissions": ["storage", "notification", "plugin-communicate"],
  "sandboxLevel": 1
}
```

`name` 是插件的**唯一标识**，同时被当作目录名与存储命名空间，因此字符集受限
（字母数字与 `.` `_` `-`，字母数字开头，最长 64）。详见[清单文件参考](清单文件参考.md)。

`engines.loopcore` 用**只带下界**的 `>=1.0.0`。范围写窄了（例如 `^1.0.0`）会在宿主升一个
次版本后产生一条「声明不匹配」的提示，而那条提示对用户没有实际价值。

## 4. 代码骨架

### 4.1 存在性守卫与共用 React

```js
(function () {
  'use strict';
  var Modulith = window.Modulith;
  if (!Modulith) {
    console.error('[reference] 未找到 window.Modulith，插件无法加载');
    return;
  }
  var React = Modulith.React;
  var h = React.createElement;
})();
```

宿主会在执行插件代码前注入 `window.Modulith`，正常路径下这一支不会走到。但它让「插件被放在
非宿主环境里加载」这件事以一个清晰的错误结束，而不是一串 `undefined is not a function`。

**不要自己 `import React`。** 宿主与插件必须是同一份实例，否则 hooks 会报错 —— 这也是打包时
必须把 `react` / `react-dom` / `react/jsx-runtime` 标为 external 的原因。

不用 JSX 是因为这里没有构建步骤，`h(...)` 就是 `createElement` 的简写。代价是嵌套稍显啰嗦，
换来的是「打开文件就能读、改一行就能生效」。

### 4.2 上下文只能在加载期取

```js
var ctx = Modulith.createContext();   // 必须在 IIFE 顶层
```

`createContext()` 依赖「当前正在加载哪个插件」这一全局状态，在加载期之外调用会抛错。因此它在
顶层取一次并长期持有，而不是在组件的渲染函数里调。

### 4.3 一次加载注册两样东西

宿主在**一次加载结束后立即**检查注册结果，因此两处都必须是顶层同步调用：

```js
Modulith.registerModule({ id: 'reference', name: '宿主接口参考', component: Reference });
Modulith.registerCommand({ id: 'reference-notify', title: '参考插件：发一条示例通知', run: … });
```

放进 Promise 或 `setTimeout` 会被判定为「没有注册任何模块」，插件被标记为异常。

`registerCommand` 注册的是**全局搜索里的一个动作**。它和模块的区别值得注意：命令被触发时
本模块可能根本没有打开，因此它的 `run` 里不能依赖组件状态，只能用加载期取到的 `ctx`。
宿主会给命令 ID 加上 `plugin:<插件 ID>:` 前缀，因此插件卸载时能一次性摘掉它注册的全部命令。

## 5. 逐个接口

### 5.1 `storage` —— 需要 `storage`

```js
await ctx.storage.get('count', 0);   // 读取（JSON 反序列化）
await ctx.storage.set('count', 5);   // 写入（JSON 序列化）
await ctx.storage.delete('count');   // 删除
```

与 `localStorage` 的差别不只是「谁提供」：

| | `ctx.storage` | `localStorage` |
| --- | --- | --- |
| 隔离 | 按插件 ID 隔离 | 全应用共用一份命名空间 |
| 清理 | 卸载插件时一并删除 | 永久残留 |
| 值类型 | JSON 序列化，可存对象 | 只能存字符串 |
| 权限 | 需声明 `storage` | 无需声明 |

两个写法上的细节：

- **首帧不是一个假值。** 计数用 `useState(null)`，读到之前显示「正在读取…」。用 `0` 作初值
  会让每次打开都先闪一个错误的 0，再跳成真实值。
- **先更新界面再落盘。** 写盘可能失败（磁盘满、权限），但那不该让按钮看起来没反应；失败只
  记一条日志。

读取时还要逐字段兜底：**用户的数据只有一份，读失败等于数据全丢。**

### 5.2 `notifications` —— 需要 `notification`

```js
ctx.notifications.info('标题', '正文', 'dedupe-key');
```

四条（`info` / `success` / `warn` / `error`）加一个 `show`，第三参是 `dedupeKey`：
**同键且未读的通知会被合并成一条**，浮层也只在第一条弹出。没有它，一个重试循环就能把通知
中心刷满 —— 而那些真正重要的通知会被埋掉。

未声明权限时接口仍然存在，但调用被忽略（只警告一次）。因此不要靠「调用了却什么也没发生」
来判断，直接用 `ctx.notifications.isAvailable()` 问，界面据此降级提示。

只有应用内通知，没有系统级通知。

### 5.3 `events` —— 需要 `plugin-communicate`

```js
ctx.events.publish('reference.tick', { at: Date.now() });
var off = ctx.events.subscribe('reference.tick', function (event) { … });
```

订阅会自动归属到插件 ID，因此插件被禁用或卸载时宿主会一次性摘掉它的全部订阅；返回的取消
函数则用于组件卸载时主动收回。

**插件收不到自己发布的事件。** 宿主默认 `receiveOwn` 为 false，理由是「发布之后由自己订阅
来更新界面」这种写法会绕一圈回到自己，而处理函数里再发布同一主题就成了死循环。需要自己处理
自己时应当直接改状态。因此参考插件里「已收到事件」在你只装它一个时**永远是 0** —— 这不是坏了。

主题名只允许小写字母、数字与 `.` `_` `-`（最长 64 字符）；写错不会报错，而是被静默拒绝。

### 5.4 `useModuleActive` 与窗口级监听

标签页保活意味着模块被切走后**不会卸载**。`keydown`、拖放这类窗口级监听必须判断可见性：

```js
var active = Modulith.useModuleActive();
React.useEffect(function () {
  if (!active) return;              // 少了这一行，别的模块里按同一个键也会触发本插件
  window.addEventListener('keydown', onKeyDown);
  return function () { window.removeEventListener('keydown', onKeyDown); };
}, [active]);
```

这是插件最容易犯、又最难自查的错误：开发时你总停在这个模块里测试。宿主提供的是**感知能力**
而不是强制暂停 —— JS 里拿不到模块创建的 timer 句柄，无法可靠地代为暂停。

### 5.5 `logger`

输出到控制台（开发者工具）。**用户看不到它。** 要让人看见，用通知；要留下痕迹，写进存储。
参考插件每次操作都同时记一条日志与一条界面上的调用记录，正是为了说明这个分工。

### 5.6 样式与深色模式

样式写在插件自己的 `index.css` 里：

- 类名加插件专属前缀（这里是 `rf-`），避免与宿主或其它插件冲突；
- 颜色复用宿主的 `--accent-*` 变量，于是跟随用户选的主题配色；
- 为 `:root.dark` 补一份深色样式，否则深色模式下会得到一片浅色方块。

**不要用 Tailwind 工具类。** Tailwind 是在构建宿主时扫描源码生成类名的，插件运行时才注入，
它写的 `bg-white` 不在那次扫描里，因此不会生成对应规则 —— 「有时能用」只是因为那个类名恰好
被宿主自己用到了。

根元素用 `position: absolute; inset: 0` 铺满**模块可见区域**（宿主每个标签的滚动容器就是最近
的定位祖先），这样不必写死 `calc(100vh - 76px)` 这类算式 —— 那种算式把标题栏与二级标题栏的
高度抄了一份，宿主一改就错位。

## 6. 三个完整示例的关键设计

### 6.1 notes：把「不多做」当成设计

它只有一个数据字段 `text`：没有标题、没有排序、没有分组、没有搜索。**速记不是写文档** ——
想法出现时不该先决定「它该叫什么名字、放哪个分类」。多加一个字段就多一次让用户做决定的
机会，而速记的全部价值就是快。

草稿与已保存条目分开存：输入框内容 400ms 防抖落盘（打了一半关窗再回来应当还在），已保存的
条目则只在点「保存」时写入 —— 显式保存 + 明确反馈，比「大概存了吧」更让人放心。

### 6.2 pomodoro：计时核心放在 React 之外

番茄钟的全部意义是「你去干别的，到点提醒你」。如果计时挂在组件里，**从未打开过这个模块就
什么都不会发生**。因此它的计时器与状态放在 React 之外：

```js
var core = { settings, timer, stats };      // 模块级状态
window.setInterval(tick, 200);              // 模块级心跳，与是否挂载无关
React.useEffect(function () { return subscribe(forceRender); }, []);   // 界面只是订阅者
```

两个与之配套的决定：

- **剩余时间始终由 `endsAt` 与当前时间算出**，而不是每个 tick 减一次。后者会在窗口被后台
  节流、系统休眠时越走越慢，而用户对番茄钟的期待是「墙上时钟走了 25 分钟」。
- **只在显示的秒数变化时才通知订阅者**，否则每秒会触发五次重渲染。

默认提示音是**用 WebAudio 现场合成**的，因此插件包里不需要带任何音频资源。注意浏览器的自动
播放策略：音频要在用户手势里先「解锁」，所以它在用户点「开始」时建立并 `resume()` 一个
`AudioContext`，之后到点播放才不会被拒绝。

### 6.3 quick-launch：需要原生能力的插件

它用到四类宿主能力：启动程序（`process-spawn`）、提取文件图标与在文件管理器中定位、接收拖入
的文件（后三项同归 `filesystem-read`）。两个值得记住的点：

- **弹窗要自己限制在模块区域内。** `position: fixed` 是相对窗口定位的，直接 `inset: 0` 会盖住
  标题栏与二级标题栏。要实测最近的可滚动祖先的可见矩形来定位；而且**必须用 `ResizeObserver`
  观察那个容器**，不能只监听 `window.resize` —— 折叠侧边栏改的是 `main` 的 `margin`，窗口尺寸
  并没有变。
- **拖放事件是窗口级的**，订阅前要判断模块是否可见，否则会在后台抢走本该属于其它模块的拖入。

## 7. 一个容易踩的坑：`check:samples` 是按文本扫描的

`pnpm check:samples` 会扫描 `samples/*/index.js` 里所有形如 `ctx.` 加服务名的片段 ——
**包括注释** —— 再与清单的 `permissions` 比对。两种不一致都算失败：

- 代码用了某能力、清单没声明 → 运行时会被拒绝，而且是用户点到那一步才发现；
- 清单声明了、代码里没用到 → 用户在安装确认页会看到一条并不存在的能力。

因此参考插件的注释里提到原生能力时只写接口名（`launcher` / `icons` / `shell` /
`fileDrop` / `audio`），没有加 `ctx.` 前缀 —— 加了就会被算作「本插件用到了它」。
写自己的插件时，这条规则的另一个方向同样值得留神：**声明要跟着代码走**。

## 8. 安装与验证

| 方式 | 操作 | 用途 |
| --- | --- | --- |
| 从插件包 | 设置 > 插件 > 安装插件 > 从插件包，选择 `samples/reference.lcp` | 验证分发形态 |
| 从本地目录 | 设置 > 插件 > 安装插件 > 从本地目录，选择 `samples/reference` 目录 | 改完源码立刻验证 |

改完源码后要**重新打包**才能真正从包安装到新代码（见第 2 节）：

```powershell
Compress-Archive -Path .\samples\reference\* -DestinationPath .\samples\reference.lcp -Force
```

想在真实分发链路上验证，就用插件市场装插件仓库里的那三个 —— 它们走的是 CDN 下载 + 哈希校验
的完整流程。

## 9. 可复用的模式

1. **顶层取上下文、注册模块与命令**，组件里只用 `ctx`。
2. **权限按需声明**：用不到就不写，多写一项就是对用户多一分误导。
3. **先想清楚这个插件到底该做什么。** 字段每多一个，就多一次让用户做决定的机会。
4. **存储键名只用字母数字 `.` `_` `-`**，事件主题名只用小写字母、数字与 `.` `_` `-`。
5. **读取时逐字段兜底**，读失败等于数据全丢；格式改版也要兼容旧数据。
6. **先更新界面再落盘**，失败只记日志 —— 写盘失败不该让按钮看起来没反应。
7. **窗口级监听（快捷键、拖放）必须判断模块可见性。**
8. **不要订阅自己发布的主题**（宿主默认也不让你收到），状态改动直接改状态。
9. **弹窗用实测的模块可见矩形定位**，不要写死标题栏高度。
10. **样式写进插件自己的 CSS**，颜色复用宿主的 `--accent-*` 并为 `:root.dark` 补一份。
