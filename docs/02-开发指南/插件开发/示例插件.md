# 示例插件解析

仓库中的 `samples/hello-plugin/` 是一个完整可运行的插件，也是本文档中各处示例的来源。本文逐部分解析它的实现，说明每个设计选择的原因。

## 1. 演示内容

| 环节 | 位置 |
| --- | --- |
| 清单声明 | `manifest.json` |
| 注册模块 | `dist/index.js` 中的 `Modulith.registerModule(...)` |
| 插件独立存储 | `dist/index.js` 中的 `ctx.storage.get` / `set` |
| 样式注入 | 清单的 `style` 指向 `dist/index.css` |
| 自定义图标 | 清单的 `icon` 指向 `icon.svg` |
| 说明文档 | 根目录的 `README.md`，展示在插件详情中 |

它同时提供了两个版本的载体：可直接安装的 `samples/hello-plugin.lcp`，以及可修改的源码目录。

## 2. 目录结构

```
hello-plugin/
  manifest.json       清单
  icon.svg            图标
  dist/
    index.js          代码包（IIFE）
    index.css         样式
  README.md           说明
```

`dist/index.js` 是手工编写的 IIFE，等价于打包器的输出结果。选择手写是为了让示例不依赖任何构建工具，直接可读。

## 3. 清单解析

```json
{
  "name": "com.modulith.sample.notes",
  "displayName": "速记本",
  "version": "1.0.0",
  "description": "示例插件：演示如何注册模块、使用插件独立存储、注入样式与自定义 SVG 图标。安装后会在侧边栏与仪表盘出现「速记本」。",
  "author": {
    "name": "Modulith Samples",
    "url": "https://example.com"
  },
  "license": "MIT",
  "homepage": "https://example.com/modulith/samples/notes",
  "categories": ["示例", "效率"],
  "keywords": ["sample", "notes", "demo"],
  "engines": {
    "loopcore": ">=1.0.0"
  },
  "main": "dist/index.js",
  "style": "dist/index.css",
  "icon": "icon.svg",
  "permissions": ["storage"],
  "sandboxLevel": 1
}
```

关键字段的作用：

| 字段 | 作用 |
| --- | --- |
| `name` | 插件 ID，同时是安装目录名与存储命名空间 |
| `displayName` | 界面中显示的名称 |
| `engines.loopcore` | 兼容的宿主版本范围 |
| `main` | 代码包路径 |
| `style` | 样式表路径，加载时注入页面 |
| `icon` | 图标路径，`.svg` 结尾会被作为文件读取 |
| `permissions` | 权限声明 |

两点值得说明：

`engines.loopcore` 使用 `>=1.0.0`（只带下界）—— 这是推荐写法：它表达"需要 1.0.0 及以上"，且不会因为宿主升个次版本就产生提示。执行 `pnpm ver check` 会对此给出提示。

`permissions` 中的 `storage` 在当前实现下不产生限制——插件存储始终可用。它作为声明的意义在于表达插件的意图，便于用户判断。

## 4. 代码包结构

`dist/index.js` 的整体骨架：

```js
(function () {
  'use strict';

  // 1. 取得宿主接口，并做存在性守卫
  var Modulith = window.Modulith;
  if (!Modulith) {
    console.error('[speed-notes] window.Modulith 不存在，宿主未就绪');
    return;
  }

  // 2. 使用宿主的 React 实例
  var React = Modulith.React;
  var h = React.createElement;

  // 3. 在加载期取得绑定到本插件的服务
  var ctx = Modulith.createContext();

  var STORAGE_KEY = 'notes';

  // 4. 定义组件
  function Notes() {
    /* ... */
  }

  // 5. 注册模块
  Modulith.registerModule({
    id: 'sampleNotes',
    name: '速记本',
    displayName: '速记本',
    description: '示例插件：本地速记，数据存放在插件自己的存储中',
    icon: 'icon.svg',
    priority: 30,
    category: '示例',
    component: Notes,
  });
})();
```

### 4.1 存在性守卫

```js
var Modulith = window.Modulith;
if (!Modulith) {
  console.error('[speed-notes] window.Modulith 不存在，宿主未就绪');
  return;
}
```

宿主在加载插件之前注入 `Modulith`，因此正常情况下不会走到这个分支。保留守卫的意义在于：如果代码包被宿主之外的场景加载（例如误在浏览器中直接打开），会输出明确原因而不是抛出难以定位的异常。

### 4.2 共用 React 实例

```js
var React = Modulith.React;
var h = React.createElement;
```

示例使用 `createElement` 而不是 JSX，因为它是手写文件、没有编译步骤。这与「使用宿主 React」是两件独立的事：无论写法如何，React 实例都必须来自 `Modulith`。

若使用打包器与 JSX，编译产物会引用 `react/jsx-runtime`，此时需要把该模块外部化并映射到 `Modulith`，配置方式见[快速开始](快速开始.md)第 9 节。

### 4.3 加载期取上下文

```js
var ctx = Modulith.createContext();
```

这一行在 IIFE 顶层执行，处于宿主设置的加载窗口内。上下文包含 `pluginId`、`pluginVersion`、`manifest`、`version` 以及 `storage`、`http`、`logger` 三个服务。

组件内部通过闭包引用这个 `ctx`，不会再次调用 `createContext()`。

## 5. 数据持久化

示例用插件的私有存储实现数据持久化：

```js
function Notes() {
  var notesState = React.useState([]);
  var notes = notesState[0];
  var setNotes = notesState[1];

  var loadedState = React.useState(false);
  var loaded = loadedState[0];
  var setLoaded = loadedState[1];

  // 首次挂载时读取
  React.useEffect(function () {
    var alive = true;
    ctx.storage
      .get(STORAGE_KEY, [])
      .then(function (saved) {
        if (alive && Array.isArray(saved)) setNotes(saved);
      })
      .catch(function (err) {
        ctx.logger.error('读取失败', err);
      })
      .then(function () {
        if (alive) setLoaded(true);
      });
    return function () {
      alive = false;
    };
  }, []);

  // 写入
  function persist(next) {
    setNotes(next);
    ctx.storage.set(STORAGE_KEY, next).catch(function (err) {
      ctx.logger.error('保存失败', err);
    });
  }
  /* ... */
}
```

这段代码有三个值得注意的处理：

**`alive` 标志**。异步读取可能在组件卸载后才完成，届时调用 `setNotes` 会触发「更新已卸载组件」的警告。用一个在清理函数中置为 `false` 的局部变量拦截，是标准的防御写法。

**先更新界面再落盘**。`persist` 先调用 `setNotes`，再异步写入存储。界面响应不等待磁盘，写入失败通过日志报告。对于这类本地记录场景，这个取舍是合适的。

**`loaded` 状态**。区分「尚未读取完」与「读取完但没有数据」两种状态，因为二者需要不同的界面。缺少这个状态时，用户会先看到「还没有速记」再突然出现内容。

读取时使用 `get(STORAGE_KEY, [])` 提供的默认值，且对返回值做 `Array.isArray` 校验，因此存储内容损坏或类型不符时不会导致渲染崩溃。

### 5.1 为什么不用 localStorage

插件的存储服务按插件 ID 隔离，并在卸载插件时清除。`localStorage` 既不隔离也不清理，留存的孤儿数据会持续占用空间且难以定位来源。

## 6. 界面构建

组件用 `createElement` 构建界面，可归纳为三个部分：

```js
h('div', { className: 'lc-notes' },
  // 头部：标题与计数
  h('header', { className: 'lc-notes__head' }, /* ... */),

  // 输入区
  h('div', { className: 'lc-notes__compose' },
    h('textarea', {
      value: draft,
      onChange: function (e) { setDraft(e.target.value); },
      onKeyDown: function (e) {
        if ((e.ctrlKey || e.metaKey) && e.key === 'Enter') add();
      },
    }),
    h('button', { onClick: add, disabled: !draft.trim() }, '保存')
  ),

  // 列表：三态渲染
  !loaded
    ? h('p', { className: 'lc-notes__empty' }, '加载中…')
    : notes.length === 0
      ? h('p', { className: 'lc-notes__empty' }, '还没有速记，写下第一条吧')
      : h('ul', { className: 'lc-notes__list' },
          notes.map(function (note) {
            return h('li', { key: note.id }, /* ... */);
          })
        )
);
```

列表的渲染用一个嵌套三元表达式覆盖三种状态：加载中、空、有数据。列表项提供了 `key`，这是 React 列表渲染的必要条件。

输入框同时处理了按钮点击与 `Ctrl`/`Cmd` + `Enter` 快捷键，前者是主要路径，后者是效率路径。

## 7. 样式隔离

`dist/index.css` 中的所有类名都带有 `lc-notes` 前缀：

```css
/* 类名统一加 lc-notes 前缀，避免污染宿主样式 */
.lc-notes { /* ... */ }
.lc-notes__head { /* ... */ }
.lc-notes__badge { /* ... */ }
```

这是必要的：样式在加载时被注入 `<style>` 元素并作用于整个文档，与宿主样式处于同一作用域。使用通用类名（如 `.list`、`.button`）会覆盖宿主或其他插件的样式。

命名采用 BEM 风格（块 `lc-notes`、元素 `lc-notes__head`），便于阅读与避免嵌套过深。

配色沿用了宿主的主色（`#4f46e5`、`#eef2ff`），使插件在视觉上与宿主一致。

## 8. 图标

`icon.svg` 是一个简单的文档图标：

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none"
     stroke="#4f46e5" stroke-width="1.8" stroke-linecap="round" stroke-linejoin="round">
  <path d="M4 4.5A1.5 1.5 0 0 1 5.5 3H16l4 4v12.5A1.5 1.5 0 0 1 18.5 21h-13A1.5 1.5 0 0 1 4 19.5z" fill="#eef2ff"/>
  <path d="M15.5 3v4.5H20"/>
  <line x1="8" y1="12" x2="16" y2="12"/>
  <line x1="8" y1="15.5" x2="13.5" y2="15.5"/>
</svg>
```

它被内联渲染，因此可以直接使用 `currentColor` 之外的固定颜色，也可以使用 CSS 变量。使用 `viewBox` 而不指定宽高，可以让图标按容器尺寸缩放。

## 9. 安装与验证

两种方式：

| 方式 | 操作 | 适用场景 |
| --- | --- | --- |
| 从插件包 | 设置 > 插件 > 安装插件 > 从插件包，选择 `hello-plugin.lcp` | 验证分发形态 |
| 从本地目录 | 设置 > 插件 > 安装插件 > 从本地目录，选择 `hello-plugin` 目录 | 修改代码后快速验证 |

安装成功后，侧边栏会立即出现「速记本」。添加几条记录后关闭再打开应用，内容应当保留——这验证了存储服务确实落盘。

若要从源码重新打包：

```powershell
Compress-Archive -Path .\samples\hello-plugin\* -DestinationPath .\hello-plugin.lcp
```

## 10. 可复用的模式

这个示例中值得沿用的做法：

| 模式 | 原因 |
| --- | --- |
| IIFE 顶层做存在性守卫 | 加载环境异常时给出明确原因 |
| 顶层取一次 `createContext()` | 服务只在加载期可用，组件内闭包复用 |
| 异步读取用 `alive` 标志防护 | 避免卸载后更新状态 |
| 读取时提供默认值并校验类型 | 存储内容损坏不致崩溃 |
| 界面先更新、存储后写入 | 交互响应不等待磁盘 |
| 区分「加载中」与「空」 | 避免内容闪烁 |
| 类名加插件专属前缀 | 样式注入全局作用域，必须避免冲突 |
| 存储用 `ctx.storage` | 按插件隔离且随卸载清理 |
