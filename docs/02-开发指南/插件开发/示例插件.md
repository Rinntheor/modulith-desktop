# 示例插件解析

仓库里有三个可运行的示例插件，各自侧重一面：

| 示例 | 侧重 | 参与的宿主能力 |
| --- | --- | --- |
| [`samples/notes`](../../../samples/notes/) | 一个完整插件的基本形态，只用一项权限 | `ctx.storage` |
| [`samples/pomodoro`](../../../samples/pomodoro/) | 后台计时、应用内通知、自定义提示音 | `ctx.storage`、`ctx.notifications`、`ctx.audio` |
| [`samples/quick-launch`](../../../samples/quick-launch/) | 需要宿主原生能力的插件怎么写 | `ctx.storage`、`ctx.launcher`、`ctx.icons`、`ctx.shell`、`ctx.fileDrop` |

**本文以 `notes` 为主线**逐部分解析，因为它的权限面最小、最容易看懂全貌；
另外两个示例的关键设计在本页末尾各有一节，详细的写在它们各自的 `README.md` 里。

三个示例的源码都在插件**根目录**（`main` 指向 `index.js`），都是手写的立即执行函数
（IIFE），**没有一个需要先搭构建工具链**。

## 1. 演示内容

`notes` 是一个「文本速记」：条目列表、全文搜索、置顶、三种排序、自动保存、
快捷键（`Ctrl+N` / `Ctrl+S`）。

只用了一项权限 `storage` —— 这本身就是个结论：**多数插件不需要申请危险权限**。
只有当它真的要执行本机程序、读本机文件或发通知时，才该在清单里多写一项。

## 2. 目录结构

```
notes/
├── manifest.json      清单（只声明 storage）
├── icon.svg           图标（SVG 文本会被直接内联渲染）
├── index.js           手写 IIFE，无构建步骤
├── index.css          插件自带样式
└── README.md          会显示在插件详情抽屉里
```

打成 `.lcp` 就是把该目录压缩后改扩展名：

```powershell
Compress-Archive -Path .\samples\notes\* -DestinationPath .\samples\notes.lcp -Force
```

**`main` 指向根目录的 `index.js` 而不是默认的 `dist/index.js`。** 默认值只是约定，
不是要求；示例刻意绕开 `dist/`，一是因为仓库的 `.gitignore` 排除了所有 `dist`
目录，二是因为「源码就在你眼前」比「源码在构建产物背后」更适合当范例。

> **`.lcp` 必须与源码目录逐字节一致。** 改完插件忘记重新打包，用户装到的就还是旧代码。
> 这条由 `extracts_and_validates_real_sample_lcps` 测试守着 —— 它解压每个 `.lcp`，
> 逐个文件与源码目录比对，同时校验清单。**这个错误我犯过两次，所以现在有测试兜着。**

## 3. 清单解析

```json
{
  "name": "com.modulith.sample.notes",
  "displayName": "文本速记",
  "version": "1.0.0",
  "engines": { "loopcore": ">=1.0.0" },
  "main": "index.js",
  "style": "index.css",
  "icon": "icon.svg",
  "permissions": ["storage"],
  "sandboxLevel": 1
}
```

`name` 是插件的**唯一标识**，同时被当作目录名与存储命名空间，因此字符集受限
（字母数字与 `.` `_` `-`，字母数字开头，最长 64）。详见[清单文件参考](清单文件参考.md)。

`engines.loopcore` 用**只带下界**的 `>=1.0.0`。这是推荐写法：范围写窄了
（例如 `^1.0.0`）会在宿主升一个次版本后产生一条「声明不匹配」的提示，
而那条提示对用户没有实际价值 —— 见 `evaluate_engine` 的说明。

## 4. 代码组织

### 4.1 存在性守卫

```js
(function () {
  'use strict';
  var Modulith = window.Modulith;
  if (!Modulith) {
    console.error('[notes] 未找到 window.Modulith，插件无法加载');
    return;
  }
  // …
})();
```

宿主会在执行插件代码前注入 `window.Modulith`，正常路径下这一支不会走到。
但它让「插件被放在非宿主环境里加载」这件事以一个清晰的错误结束，而不是
一串 `undefined is not a function`。

### 4.2 共用 React 实例

```js
var React = Modulith.React;
var h = React.createElement;
```

**不要自己 `import React`。** 宿主与插件必须是同一份 React 实例，否则 hooks
会报错 —— 这也是打包时必须把 `react` / `react-dom` / `react/jsx-runtime`
标为 external 的原因。

不用 JSX 是因为这里没有构建步骤，`h(...)` 就是 `createElement` 的简写。
代价是嵌套稍显啰嗦，换来的是「打开文件就能读、改一行就能生效」。

### 4.3 上下文只能在加载期取

```js
var ctx = Modulith.createContext();   // 必须在 IIFE 顶层
```

`createContext()` 依赖「当前正在加载哪个插件」这一全局状态，在加载期之外调用会抛错。
因此它在顶层取一次并长期持有，而不是在组件的渲染函数里调。

同理，`Modulith.registerModule(...)` 也必须在**顶层同步调用** —— 宿主按
「加载结束时是否注册过模块」判断插件是否加载成功。

## 5. 数据持久化：索引与正文分开存

```js
var INDEX_KEY = 'notes';        // 元数据：标题、摘要、置顶、时间、排序、选中项
var BODY_PREFIX = 'note.';      // 每条正文各占一个键：note.<id>
```

**为什么不把正文放进索引里**：那样「改一个字」就要重写整份数据（所有条目的
全部正文）。分开之后，打字只写当前这一条，索引始终保持很小。

还有一处细节值得注意：键名用 `note.` 而不是 `note:` —— 存储键只允许字母数字与
`.` `_` `-`，冒号会被后端直接拒绝。

### 5.1 读取时容错

```js
function normalizeIndex(raw) {
  if (!raw || typeof raw !== 'object') return emptyIndex();
  // …逐字段兜底，并丢弃指向已删除分组的引用
}
```

**读的时候容错比写的时候谨慎更重要。** 用户的数据只有一份，读失败就全丢了。
这里对每个字段都给了默认值，并且会把「指向不存在条目的 selectedId」清掉 ——
否则界面会停在一个空白编辑器上，而用户看不出为什么。

### 5.2 不用 localStorage

`ctx.storage` 与 `localStorage` 的差别不只是「谁提供」：

| | `ctx.storage` | `localStorage` |
| --- | --- | --- |
| 隔离 | 按插件 ID 隔离 | 全应用共用一份命名空间 |
| 清理 | 卸载插件时一并删除 | 永久残留 |
| 值类型 | JSON 序列化，可存对象 | 只能存字符串 |
| 权限 | 需声明 `storage` | 无需声明 |

## 6. 自动保存：防抖 + 切走时落盘

两条合起来才叫「不会丢」：

```js
// 1) 打字时防抖，600ms 没有新输入才写盘
timerRef.current = setTimeout(flushSave, 600);

// 2) 模块被切走时立刻落盘
var active = Modulith.useModuleActive();
React.useEffect(() => {
  if (active) return;
  flushSave();
}, [active, flushSave]);
```

**为什么第 2 条不能省。** 标签保活意味着切走**不会卸载**这个模块，计时器照跑 ——
但用户随时可能关窗。那 600ms 的防抖窗口里如果没有第 2 条，最后几个字就没了。
切走是最常见的「我要走了」信号，用它做一次落盘几乎零成本。

顺带一个必须处理的细节：`flushSave` 用 `useRef` 读写最新的草稿与索引。
如果它闭包捕获了 `useState` 的值，防抖回调看到的会是**旧值**，
表现就是「最后一段输入被上一次的内容覆盖」。

## 7. 全文搜索：按需加载正文

搜索要搜全文，但不能为了搜索把正文塞进索引（那就回到第 5 节的问题了）。
折中办法是**第一次搜索时**才把所有正文读进内存：

```js
React.useEffect(() => {
  if (!index || bodiesReady || !query.trim()) return;
  Promise.all(index.items.map((item) =>
    ctx.storage.get(BODY_PREFIX + item.id, '').then((body) => {
      bodiesRef.current[item.id] = body;
    })
  )).then(() => setBodiesReady(true));
}, [index, query, bodiesReady]);
```

平时完全不读；代价是第一次搜索有一个短暂的加载。条目增删后缓存失效，重新加载。

## 8. 界面构建与样式

界面部分只是普通的 React：列表、编辑器、错误条。三处与「插件」身份有关的取舍：

**快捷键必须判断模块是否可见。** `keydown` 挂在 `window` 上，是窗口级的：

```js
React.useEffect(() => {
  if (!active) return;            // 少了这一行，在别的模块按 Ctrl+N 也会新建速记
  window.addEventListener('keydown', onKey);
  return () => window.removeEventListener('keydown', onKey);
}, [active, create, flushSave]);
```

**样式用插件自带的 `index.css`，不用 Tailwind 工具类。** Tailwind 是在**构建宿主时**
扫描源码生成类名的，插件是运行时才注入的 —— 它写的 `class="bg-white"` 不在那次扫描里，
不会生成对应规则。「有时能用」只是因为那个类名恰好被宿主自己用到了。

**配色复用宿主的 CSS 变量**（`--accent-*`），深色模式则由宿主在 `:root` 上加 `.dark`
切换，插件只需要为这套选择器再写一份：

```css
.nt-item-active { background: var(--accent-50); }
:root.dark .nt-item-active { background: rgba(255, 255, 255, 0.07); }
```

### 8.1 让界面铺满模块区域

`notes` 的根元素用了 `position: absolute; inset: 0`：

```css
.nt-root { position: absolute; inset: 0; display: flex; flex-direction: column; }
```

宿主的模块滚动容器（`.lc-tab-panel`）本身是 `position: absolute` 的，因此它就是
最近的定位祖先 —— `inset: 0` 正好等于**模块可见区域**。于是两栏布局可以各占一半
高度、各自内部滚动，而不必写死 `calc(100vh - 76px)` 这类算式（那种算式把标题栏与
二级标题栏的高度抄了一份，宿主一改就错位）。

## 9. 另外两个示例的关键点

### 9.1 pomodoro：计时核心放在 React 之外

番茄钟的全部意义是「你去干别的，到点提醒你」。如果计时挂在组件里，
**从未打开过这个模块就什么都不会发生**。因此它的计时器与状态放在 React 之外：

```js
var core = { settings, timer, stats };      // 模块级状态
window.setInterval(tick, 200);              // 模块级心跳，与是否挂载无关
React.useEffect(() => subscribe(forceRender), []);   // 界面只是订阅者
```

两个与之配套的决定：

- **剩余时间始终由 `endsAt` 与当前时间算出**，而不是每个 tick 减一次。
  后者会在窗口被后台节流、系统休眠时越走越慢，而用户对番茄钟的期待是
  「墙上时钟走了 25 分钟」。
- **只在显示的秒数变化时才通知订阅者**，否则每秒会触发五次重渲染。

提示音方面，默认音是**用 WebAudio 现场合成**的（两个正弦音，上行/下行区分去向），
因此插件包里不需要带任何音频资源；用户也可以用 `ctx.audio.pick()` 导入自己的文件替换。
注意浏览器的自动播放策略：音频要在用户手势里先「解锁」，所以它在用户点「开始」时
建立并 `resume()` 一个 `AudioContext`，之后到点播放才不会被拒绝。

### 9.2 quick-launch：需要原生能力的插件

它用到四类宿主能力：启动程序（`process-spawn`）、提取文件图标与在文件管理器中定位、
接收拖入的文件（后三项同归 `filesystem-read`）。

两个值得记住的点：

- **弹窗要自己限制在模块区域内。** `position: fixed` 是相对窗口定位的，直接
  `inset: 0` 会盖住标题栏与二级标题栏。要实测最近的可滚动祖先的可见矩形来定位；
  而且**必须用 `ResizeObserver` 观察那个容器**，不能只监听 `window.resize` ——
  折叠侧边栏改的是 `main` 的 `margin`，窗口尺寸并没有变。
- **拖放事件是窗口级的**，订阅前要判断模块是否可见，否则会在后台抢走本该属于
  其它模块的拖入。

| 从插件包 | 设置 > 插件 > 安装插件 > 从插件包，选择 `samples/notes.lcp` | 验证分发形态 |
| 从本地目录 | 设置 > 插件 > 安装插件 > 从本地目录，选择 `samples/notes` 目录 | 改完源码立刻验证 |

改完源码后要**重新打包**才能真正从包安装到新代码（见第 2 节的说明）：

```powershell
Compress-Archive -Path .\samples\notes\* -DestinationPath .\samples\notes.lcp -Force
```

## 11. 可复用的模式

1. **顶层取上下文与注册模块**，组件里只用 `ctx`。
2. **权限按需声明**：用不到就不写，多写一项就是对用户多一分误导。
3. **索引与正文（大对象）分开存**，别让改一个字重写整份数据。
4. **存储键名只用字母数字 `.` `_` `-`**。
5. **读取时逐字段兜底**，读失败等于数据全丢。
6. **防抖保存 + 切走时落盘**，两条合起来才叫不会丢。
7. **窗口级监听（快捷键、拖放）必须判断模块可见性。**
8. **弹窗用实测的模块可见矩形定位**，不要写死标题栏高度。
9. **样式写进插件自己的 CSS**，颜色复用宿主的 `--accent-*` 并为 `:root.dark` 补一份。
